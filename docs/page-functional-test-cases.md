# VR 大空间预约系统 · 按网页功能模块的测试案例

> 本方案按“页面 = 功能模块”梳理，覆盖管理后台（`app`）与 C 端（`app/reservation`）的核心测试点。适用于 E2E、接口集成测试或手工测试用例设计。

---

## 一、测试分层建议

| 测试类型 | 适用场景 | 工具建议 |
|---|---|---|
| **单元测试** | 页面内纯函数、Hooks、工具函数 | Vitest + @testing-library/react |
| **集成/API 测试** | 页面与后端接口的联调、数据一致性 | Vitest / Playwright / Postman |
| **E2E 测试** | 完整用户流程、权限矩阵、UI 交互 | Playwright |

下面按页面列出的是**功能/集成/E2E 层面**的测试案例。

## 二、管理后台（`app/src`）

### 公共与认证

#### `/login` 登录页
| 分类 | 测试点 |
|---|---|
| 正常流程 | 正确手机号+密码登录 → 跳转首页；token/refreshToken 写入存储；`queryClient.clear()` 执行 |
| 异常流程 | 错误密码/不存在的手机号提示失败；空手机号/空密码前端拦截；网络超时提示 |
| 边界 | 超长手机号、特殊字符密码、密码明文/密文切换 |
| 联动 | 登录成功后 Sidebar 菜单按权限渲染；未登录访问受保护路由跳转 `/login` |

### 3.3 普通预约与支付

#### `/confirm` 订单确认
| 分类 | 测试点 |
|---|---|
| 入口 | 由 `VenueDetail` 通过 `location.state` 进入，无 state 报错 |
| 正常流程 | 填写人数/姓名/电话；选择优惠券；实时校验冲突；创建 booking + order；跳转支付 |
| 异常流程 | 姓名/电话为空；人数超过剩余可拼人数；提交前场次被占；团购套餐人数不在范围 |
| 联动 | 人数变化 → 总价变化；优惠券选择 → 体验券先抵扣 1 人，再会员折扣，再折扣券；登录后自动填充联系人 |

| 分类 | 测试点 |
|---|---|
| 正常流程 | 默认余额支付；余额不足默认微信并提示充值；选择平台券后应付金额减少；支付成功跳转 `/orders` |

|---|---|

## 四、跨页面通用测试矩阵

### 4.1 权限矩阵（建议用 Playwright 做 E2E）

| 角色 | 测试范围 |
|---|---|
| `SUPER_ADMIN` | 所有路由、菜单、按钮可见且可操作 |
| `ADMIN` / `MANAGER` | 按角色权限可见对应模块；无权限路由重定向首页并提示 |
| `OPERATOR` | 只能看到订单/预约相关；财务/设置/角色不可见 |
| `FINANCE` | 可见财务、审计日志；不可操作订单核销/退款 |
| 未登录 | 访问任何受保护路由跳转 `/login`；C 端 `/` 和 `/venues` 等可匿名访问 |

### 4.2 路由守卫

| 测试点 | 期望 |
|---|---|
| 未登录访问 `/orders` | 跳转 `/login` |
| 未登录访问 `/booking` | 跳转 `/login` |
| 登录后访问 `/login` | 跳转 `/` |
| C 端 `/reservation`（后台页面） | `AuthGuard` 放行 |

### 4.3 数据一致性与联动

| 场景 | 期望 |
|---|---|
| 后台新建场地 | 首页、C 端首页、场地列表可见 |
| 后台修改游戏价格 | C 端详情与订单确认页价格同步 |
| 后台修改退款规则 | C 端 `/refund` 与订单取消逻辑同步 |
| 后台审批通过退款 | 订单状态变为已退款，财务流水生成 |
| C 端支付成功 | 我的订单、个人中心余额/积分、后台订单列表同步 |
| C 端取消订单 | 释放场次，后台订单状态同步 |

### 4.4 异常与边界通用项

| 场景 | 期望 |
|---|---|
| 网络断开 | 显示 loading/骨架屏/错误提示，不白屏 |
| 空数据 | 显示空态插画/提示 |
| 分页 | 切换页码、每页条数、末页行为正确 |
| 搜索 | 支持回车/实时；无结果提示；清空后恢复 |
| 超长输入 | 前端做长度限制；后端做校验 |
| 并发操作 | 同一账号多端登录冲突处理（C 端 `authVersion`） |

## 五、建议落地步骤

1. **先补核心流程 E2E**：登录 → 预约 → 支付 → 核销 → 退款/改签 → 财务对账。
2. **再做权限矩阵自动化**：用不同角色账号遍历主要路由，断言菜单/按钮显隐。
3. **页面级回归用例**：每个页面至少覆盖“正常加载、空数据、关键操作、异常提示”四类。
4. **与单元测试互补**：页面内纯函数、Hooks 用 Vitest 覆盖；页面流程用 Playwright 覆盖。
